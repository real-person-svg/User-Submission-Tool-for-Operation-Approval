- [x] 按状态、关键词和提交时间筛选。
- [x] 服务端分页与总数展示。

## 3. 投稿详情（已实现）

- [x] 使用抽屉展示完整投稿。

## 4. 单条审核（已实现）

- [x] 通过待审核投稿。
- [x] 驳回待审核投稿，原因必填且不能只有空格。
- [x] 操作前明确展示审核对象和动作。
- [x] 提交期间禁用重复操作，成功后刷新列表。

## 5. 批量审核（已实现）

- [x] 勾选当前页的多条待审核投稿。
- [x] 显示已选数量，支持清空选择。
- [x] 分页或切换筛选条件时清空选择。
- [x] 批量通过、使用统一原因批量驳回。
- [x] 不同驳回原因的投稿分批或单独处理。

## 6. 操作人与日志（已实现）

- [x] 从已有可用审稿人中选择当前人员。
- [x] 保留已有人员数据及历史审核关联，不提供审稿人管理功能。
- [x] 未选择操作人时阻止审核。
- [x] 保存操作人、操作时间、审核动作和原因。
- [x] 用批次 ID 关联同一次批量审核产生的记录。
- [x] 支持按投稿或操作人查询审核日志。

## 9. 已实现接口

- `GET /api/operators`：可用审稿人列表。
- `GET /api/submissions`：筛选、分页查询投稿。
- `POST /api/submissions`：通过页面录入一条待审核投稿。
- `GET /api/submissions/:id`：投稿详情。
- `POST /api/reviews`：单条或批量审核。
- `GET /api/review-logs`：查询审核记录。

## 10. 范围约定

- 不实现完整账号系统，操作人选择仅用于演示归属。
- 第一版不提供撤销审核、重新送审或通知功能。
- 题目没有明确的规则以本文件约定为准；正式开发前可以调整。
